# Plan: عرض رسالة "افتح التطبيق أولاً" في الويدجت قبل توفر البيانات

## المشكلة (Problem)

لما المستخدم يضيف ويدجت من روح المسلم لشاشة الهوم أو شاشة القفل **قبل ما يفتح التطبيق ولو مرة واحدة**، الويدجت بتاخد بيانات وهمية (`sampleSharedData()`) فبيظهر فيها:

- `--:--` كقيمة للـ countdown / مواقيت الصلاة
- `Missing: <id>_<size>_<theme>` (في DEBUG فقط) داخل `BrandedFallbackView`
- بيانات نموذجية مضللة (مكة، 21 ذو القعدة 1447، آيات ثابتة، ...) — المستخدم ممكن يفتكر إنها بياناته الحقيقية ودي مشكلة UX خطيرة.

السبب الحقيقي: قبل أول فتح للأبليكيشن، مفيش حد كَتب JSON على App Group UserDefaults / `widget_data.json`، فـ `loadSharedData(SharedWidgetData.self)` بترجع `nil` وكل provider بيـ fallback لـ `sampleSharedData()` أو لبيانات تجريبية محلية.

المطلوب: نعرض جملة توضيحية واضحة تطلب من المستخدم يفتح التطبيق الأول، بدل البيانات الوهمية والـ`--:--`، عبر:

- **Home screen widgets** (PNG snapshot path في `RoohWidgets.swift`)
- **Lock screen widgets** (SwiftUI native path في `RoohWidgets.swift`)
- **Legacy SwiftUI providers** (`NextPrayerWidget`, `AzkarWidget`, `QuranAyahWidget`, `DhikrWidget`, `HijriDateWidget`)

ملاحظة: Live Activity و Control Widgets (iOS 18+) خارج النطاق لأنهم ما بيظهروش قبل أول تشغيل للأبليكيشن أصلاً.

## المطلوب نعمله (Solution)

### الفكرة الرئيسية

نضيف **detector** بسيط يقول هل في `SharedWidgetData` متاحة فعلاً ولا لأ، وإذا لأ نعرض **`AppNotOpenedView`** (View جديد) محله محل أي داتا أو fallback نموذجي.

### تعريف "البيانات غير متاحة"

البيانات تعتبر **مش متاحة** (المستخدم ما فتحش الأبليكيشن) لما **كل** الشروط دي تتحقق:

1. `loadSharedRawData()` ترجع `nil` (مفيش `widget_shared_data` في UserDefaults و مفيش `widget_data.json` في الـ App Group container).

أو بشكل أخف (defensive):

2. الـ JSON موجود لكن `prayer == nil && azkar == nil && verse == nil && dhikr == nil` (يعني Codable اشتغل لكن الـ payload فاضي تماماً).

هنبني helper واحد بدل ما نكرر اللوجيك:

```swift
// في RoohWidgets.swift أو WidgetBundle.swift
func sharedDataIfAvailable() -> SharedWidgetData? {
    guard let data = loadSharedRawData(),
          let decoded = try? JSONDecoder().decode(SharedWidgetData.self, from: data)
    else { return nil }
    // اعتبر الـ payload فاضي = "ما فُتحش الأبليكيشن"
    let hasAnyContent = decoded.prayer != nil
        || decoded.azkar != nil
        || decoded.verse != nil
        || decoded.dhikr != nil
        || decoded.widgetTheme != nil
        || decoded.widgetLanguage != nil
    return hasAnyContent ? decoded : nil
}
```

### الـ View الجديد — `AppNotOpenedView`

نضيفه في `RoohWidgets.swift` جنب `BrandedFallbackView` و `EmptyPlaceholderView`. يعرض:

- أيقونة (`Image(systemName: "iphone.gen3.badge.play")` أو نفس `WidgetIcon` المستخدم في BrandedFallbackView).
- نص أساسي (Headline) — حسب اللغة:
  - العربي: **«افتح تطبيق روح المسلم»**
  - الإنجليزي: **"Open Rooh Al Muslim"**
- نص تكميلي (sub) صغير:
  - العربي: **«حتى تظهر بيانات الويدجت»**
  - الإنجليزي: **"to load widget data"**
- خلفية مأخوذة من `palette()` نفس النظام الحالي (يحترم theme لو متخزن، ولو مش متخزن — `.dark` افتراضي مع رسم متناسق).
- يستخدم `widgetURL(URL(string: "rooh-almuslim://"))` عشان لما المستخدم يضغط على الويدجت يفتح التطبيق فوراً.

تحديد لغة الرسالة (priority chain):

1. لو فيه `SharedWidgetData` فيها `widgetLanguage == "ar"|"en"` → استخدمها.
2. لو SharedData موجودة وفيها `language` → استخدمها.
3. غير كده (وهي الحالة الأشيع لأن البيانات مش موجودة أصلاً): استخدم `Locale.current.language.languageCode?.identifier == "ar"`.

نعمل helper:

```swift
func widgetSystemIsArabic() -> Bool {
    if #available(iOS 16, *) {
        return Locale.current.language.languageCode?.identifier == "ar"
    }
    return Locale.current.languageCode == "ar"
}
```

### نقاط التطبيق (Touchpoints)

#### 1. `widgets/ios/RoohWidgets.swift` — Home widgets routers

في الـ entry views:

- `RoohSmallEntryView.body` (سطور 437–460 تقريباً)
- `RoohMediumEntryView.body` (سطور ~462–478)
- `RoohLargeEntryView.body` (سطور ~480–495)

حالياً كل واحد فيهم بيركّب `WidgetContext` ويمرّره لـ `WidgetImageView`. هنحط شرط في الأول:

```swift
if !sharedDataAvailable {
    AppNotOpenedView(family: .systemSmall) // أو medium / large
} else {
    // الكود الحالي بدون أي تغيير
}
```

`sharedDataAvailable` = `entry.data` ما اتعمل فيهاش fallback لـ `sampleSharedData()` — وعشان نعرف ده، أبسط طريقة:

- نخلي الـ providers (`SmallProvider`, `MediumProvider`, `LargeProvider`) ما يستخدموش `?? sampleSharedData()` كـ fallback لـ `loadSharedData`، وبدل كده نضيف flag `dataAvailable: Bool` على `RoohEntry<Configuration>` (أو نخزّن `Optional<SharedWidgetData>` ونحط `sampleSharedData()` لو مش متاحة عشان متغيّرش الـ existing rendering لما البيانات موجودة).
- البديل الأنظف: نضيف **field جديد** `var hasRealData: Bool` على `RoohEntry`:

```swift
struct RoohEntry<Configuration: WidgetConfigurationIntent>: TimelineEntry {
    let date: Date
    let configuration: Configuration
    let data: SharedWidgetData
    let hasRealData: Bool   // ← جديد
}
```

ونعدّل الـ providers:

```swift
func snapshot(...) async -> RoohEntry<...> {
    let real = sharedDataIfAvailable()
    return RoohEntry(
        date: Date(),
        configuration: configuration,
        data: real ?? sampleSharedData(),
        hasRealData: real != nil
    )
}
// نفس الشيء للـ timeline (سطر ~264, 279, 294)
```

ونضيف نفس الـ flag على `WidgetContext` (سطر 500) عشان الـ views الجوّانية تعرف:

```swift
struct WidgetContext {
    // ... الموجود
    let hasRealData: Bool
}
```

#### 2. `widgets/ios/RoohWidgets.swift` — Lock widgets

نفس النمط، لكن الـ providers في lock screen أبسط (لأنها static struct entries مش `RoohEntry`). نحدّث:

- `LockDayThuluthProvider` (~1310)
- `LockMonthThuluthProvider` (~1327)
- `LockNextPrayerProvider` (~1366)
- `LockAllPrayersProvider` (~1402)
- `LockHijriCircularProvider` (~1432)
- `LockNextPrayerCountdownProvider` (~1468)

كل واحد منهم Entry struct يضاف لها `hasRealData: Bool`. الـ providers تستعمل `sharedDataIfAvailable()` بدل `loadSharedData(...) ?? sampleSharedData()`.

في الـ EntryViews الخاصة بكل lock widget:

```swift
var body: some View {
    if !entry.hasRealData {
        LockAppNotOpenedView()  // مصغّرة عشان حجم lock widget
    } else {
        // الـ view الحالي
    }
}
```

`LockAppNotOpenedView` نسخة مختصرة من `AppNotOpenedView` تتناسب مع `accessoryRectangular` / `accessoryCircular` / `accessoryInline`. هنحدد الـ family المطلوبة من `@Environment(\.widgetFamily)` ونطبع نص مختصر:

- Inline: `"افتح روح المسلم"` / `"Open Rooh"`
- Rectangular: نفس + sub line
- Circular: أيقونة بس + نقطتين تحتها (لأنها صغيرة جداً)

#### 3. `widgets/ios/RoohWidgets.swift` — `WidgetImageView` & `BrandedFallbackView`

`WidgetImageView` (سطر 1857) لازم تعرف بـ `hasRealData` كمان:

```swift
struct WidgetImageView: View {
    let widgetId: String
    let family: WidgetFamily
    let context: WidgetContext  // الآن فيه context.hasRealData
    // ...
    var body: some View {
        if !context.hasRealData {
            return AnyView(AppNotOpenedView(family: family))
        }
        // الكود الحالي
    }
}
```

النتيجة: لما الـ snapshot PNG مش موجود **و** البيانات مش موجودة → `AppNotOpenedView` (مش `BrandedFallbackView`).
لما الـ PNG مش موجود لكن البيانات موجودة → `BrandedFallbackView` يفضل كما هو (شاشة "loading" مؤقتة لحد ما الـ snapshot pump يكتب الـ PNG).

#### 4. Legacy providers

##### `widgets/ios/NextPrayerWidget.swift`

- في `getSnapshot` / `getTimeline` (سطور 119–153): الـ entry معاها `data: PrayerWidgetData?` (already optional). هنضيف `hasRealData: Bool` على `PrayerWidgetEntry` (سطر ~95–102) ونحدد قيمتها بـ `loadData() != nil`.
- في كل View (`SmallPrayerWidgetView`, `MediumPrayerWidgetView`, `LargePrayerWidgetView`, `LargeClassicPrayerView`, ...): لو `!entry.hasRealData` نعرض `AppNotOpenedView`.
- نشيل أو نعطل `placeholder` في سطر 110 من إنه يرجع `sampleData` — يفضّل نخليه يرجع entry بـ `data: nil, hasRealData: false` عشان حتى الـ widget gallery preview يظهر النصيحة (واقعياً Apple بترسم الـ placeholder بـ redacted view على فكرة، لكن نخلّي السلوك متّسق).
- ⚠️ ممكن نخلي الـ `placeholder` يرجع `sampleData` (placeholder بيظهر في widget picker بس) ونخلي `getSnapshot`/`getTimeline` بس يستخدموا `hasRealData = false` لما البيانات مش متاحة. **نختار ده**: placeholder بيوقف على sample data (Apple bestpractice — لازم يكون representative)، لكن snapshot الفعلي (للويدجت اللي على الشاشة) بيعرض `AppNotOpenedView`.

##### `widgets/ios/AzkarWidget.swift`

نفس التعديل: `AzkarWidgetEntry` يبقى فيه `hasRealData: Bool`. الـ provider في سطور 59–86 يستعمله. الـ views الـ legacy تتعرض على شرط `entry.hasRealData`.

##### `widgets/ios/QuranAyahWidget.swift`, `DhikrWidget.swift`, `HijriDateWidget.swift`

نفس النمط: `hasRealData` في الـ Entry + شرط في الـ View.

#### 5. Sub-views/components اللي بتستخدم نص ثابت `--:--`

النصوص دي ما هتنفّذش طول ما الـ View كله متلف بـ `if hasRealData` early return — مش محتاجين نلمسها. لكن نحتفظ بـ `formatCountdown(... ?? "--:--")` zwie هي عشان تتعامل مع حالة "البيانات موجودة لكن `timeRemaining == nil`" (يعني المستخدم فتح التطبيق لكن الـ prayer engine لسه بيحسب).

## نقاط حذرة (Pitfalls)

1. **`placeholder()` بيظهر في Widget Picker**: ما نخليش `placeholder` يرجع `hasRealData: false` لأن ده هيخلّي الـ picker preview نفسه يقول "افتح التطبيق" حتى لما المستخدم لسه بس بيختار الويدجت — ده تجربة سيئة. الحل: `placeholder` يفضل يرجع sample data (placeholder بيتعرض redacted أصلاً). بس `snapshot` و `timeline` الفعليين هما اللي يطبقوا `sharedDataIfAvailable`.

2. **Theme palette لما البيانات مش موجودة**: مفيش `widgetTheme` في SharedData، فالـ `AppNotOpenedView` لازم تستخدم `palette(.dark)` كـ default (أو تحترم `colorScheme` عبر `@Environment(\.colorScheme)` لو متاح). نختار `colorScheme`-aware: `palette(.auto)` resolved بـ `resolvedRoohTheme(.auto, colorScheme: ...)`.

3. **`WidgetContext` init الموجود بيـ inferر language من `data.widgetLanguage`** (سطر 553). لو `hasRealData == false`، الـ context هيستخدم `widgetLanguage = nil` (لأن sample data ما بتحطش `widgetLanguage`) فنرجع للـ `Locale.current` — وده مظبوط.

4. **`sampleSharedData()` لازم يفضل موجود** عشان الـ placeholder، الـ widget gallery، والـ `EmptyPlaceholderView` (حالة "اختر النوع" — مختلفة عن حالتنا). مش هنحذفه.

5. **`BrandedFallbackView` يفضل** يستخدم لما PNG snapshot مش متوفر **بس** البيانات متوفرة (يعني snapshot pump لسه ما اتنفذش). ده سلوك مرحب فيه لأنه صادق: التطبيق اتفتح، الداتا متاحة، الـ snapshot بس بيتجهّز.

6. **Live Activity** (`PrayerLiveActivity.swift`) خارج النطاق لأن activity ما بيشتغلش غير من جوّا الأبليكيشن أصلاً (Apple constraint).

7. **Lock screen accessory sizes** صغيرة جداً. نتعامل معاهم بنصوص قصيرة و إيموجي مفيش، عشان `accessoryCircular` 35×35 pt تقريباً. الحل: للـ circular نعرض أيقونة فقط (`iphone.gen3.badge.play`) وتقدير في accessibility label.

## Test plan

### Manual smoke tests (يدوياً على جهاز/simulator)

1. **حالة التثبيت الجديدة**:
   - شيل التطبيق من الجهاز.
   - أعد التثبيت (مع إعادة build للـ widget extension).
   - **ما تفتحش التطبيق**.
   - أضف كل ويدجت home (small/medium/large) وكل lock widget للـ Lock Screen.
   - تحقق إن كلهم بيعرضوا `AppNotOpenedView` بالنص الصح حسب لغة الجهاز.
   - افتح التطبيق مرة واحدة، استنى ثانيتين، ارجع للـ Home — لازم الويدجت تتحدث وتعرض البيانات الحقيقية.

2. **حالة "الداتا قديمة جداً"**: مش جزء من المشكلة دلوقتي — الـ snapshot pump بيتعامل معاها.

3. **اللغة**:
   - عدّل لغة الـ iOS لـ Arabic، احذف وأضف الويدجت بدون فتح التطبيق → النص يبقى عربي.
   - عدّلها لـ English → النص يبقى إنجليزي.

4. **Widget gallery preview** (long-press على الهوم → Add Widget → Rooh):
   - الـ preview placeholders لازم يفضلوا يعرضوا الـ sample data (بـ redacted skeleton من iOS) — مش `AppNotOpenedView`.

5. **Tap-to-open**: اضغط على الويدجت اللي عارض `AppNotOpenedView` → التطبيق يفتح على الـ home (`rooh-almuslim://`).

6. **Theme**:
   - الجهاز في dark mode → خلفية `AppNotOpenedView` غامقة.
   - الجهاز في light mode → خلفية فاتحة.

### Build verification

- `xcodebuild` للـ widget extension يعدّي بدون warnings جديدة.
- TypeScript / lib code ما اتغيّرش — ما فيش حاجة تختبر من ناحية JS.

## Out of scope

- تعديل لـ `lib/widgets/snapshot.tsx` أو `pump.ts`: النظام الـ snapshot يفضل كما هو. الويدجت بس بقت أذكى في تحديد إن مفيش shared data خالص.
- Live Activity و Control Widgets (مش بتعرض داتا قبل أول فتح للأبليكيشن).
- تخزين أي بيانات افتراضية في الـ App Group من الـ AppDelegate قبل JS bridge — لو حصل في المستقبل، الشرط `sharedDataIfAvailable()` لسه شغال (هيرجع الداتا الافتراضية كـ "متاحة"، اللي ممكن يبقى السلوك المرغوب).
- `EmptyPlaceholderView` (سطر 731) — ده flow مختلف (المستخدم اختار `widget = .placeholder` صراحةً) ومش متأثر.
